# Issue 06: PostgreSQL schema + persistence CRUD + tests

## Parent

`.scratch/v1-design-overhaul/PRD.md`

## What to build

Create the PostgreSQL persistence layer. Two tables: `players` (id, token, created_at) and `commanders` (id, player_id, weapon, armor, unit_type, leading_skill, kill_points, level, formation JSONB, combat_units JSONB, created_at). The commanders table stores Formation Template and attached CombatUnits as JSONB arrays — one read loads the entire Commander with its roster.

CRUD functions:
- FindOrCreatePlayer(db, token) — idempotent, creates player on first token, returns existing on repeat
- LoadRoster(db, playerID) — returns all Commanders for a player with their Formation and CombatUnits deserialized from JSONB
- SaveCommander(db, CommanderRow) — upserts a single Commander row including JSONB
- DeleteCommander(db, commanderID) — deletes Commander (CASCADE removes nothing since CombatUnits are JSONB, not a separate table)
- CreateStarterRoster(db, playerID) — creates 1 Gun/Light Commander + 5 Light Infantry in combat_units JSONB

Migration function that creates both tables if they don't exist.

Tests use a real PostgreSQL connection (test database) to verify round-trip fidelity.
