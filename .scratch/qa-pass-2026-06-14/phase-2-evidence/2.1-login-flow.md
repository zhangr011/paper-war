## Subflow 2.1.3 — Mid-lobby WS drop, auto-reconnect

**Action:** In lobby, call `connection.ws.close()` to simulate server-side WS drop (server itself still up).
**Expected:** Connection layer detects close, triggers exponential backoff reconnect (1s → 2s → 4s), re-fires `onConnect`, App is usable again.
**Actual:** ✅ Within 2s: `connConnected: true`, `wsState: 1` (reconnected). Stayed in lobby screen. `#solo-btn.disabled === false` — match can be started immediately after reconnect.
**Result:** PASS

**Note on login auto-resent:** Login was sent on initial connect (app.js:190 `sendJSON({type:'login',name})`). On reconnect without a match token, app.js:279-282 re-sends login after `reconnect_failed`. In this test the reconnect succeeded on the first retry, so the `reconnect_failed` re-send path wasn't exercised — covered by Phase 1 crash-restart spec instead.
