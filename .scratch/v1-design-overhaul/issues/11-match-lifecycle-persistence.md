# Issue 11: Match lifecycle + token auth + periodic flush integration + tests

## Parent

`.scratch/v1-design-overhaul/PRD.md`

## What to build

Wire together the full match lifecycle: token authentication, roster loading, match start, periodic persistence flush, match end, and roster recovery.

Token auth: On WebSocket connect, extract token from URL query parameter. Call FindOrCreatePlayer (issue 06). If new player, create starter roster immediately. Load roster into memory.

Lobby: Player sees their roster (Commanders + CombatUnits). Player selects a Commander. Player clicks "Start Match". Server generates a random map with a random objective. Server creates an AI opponent with a random Commander type.

Match start: Load selected Commander's Formation Template and CombatUnits from roster. Auto-deploy highest-level CombatUnits up to Leading Skill cap. Set starting Gold = 50. Create ECS entities for all deployed units.

Periodic flush: Every 30 seconds during the match, write accumulated kill points, levels, Leading Skill, and dead unit removal to the database. On server crash, roster reverts to last successful flush.

Match end: Final flush writes surviving roster to database. Dead units removed from Commander's combat_units JSONB. Unspent Gold discarded. If player's entire roster was destroyed, immediately create a new starter roster.

Lobby changes (Commander selection, unit adjustments) use immediate write with 10-second debounce.
