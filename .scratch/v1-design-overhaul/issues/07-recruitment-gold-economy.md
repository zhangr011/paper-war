# Issue 07: RecruitmentSystem + Gold economy + tests

## Parent

`.scratch/v1-design-overhaul/PRD.md`

## What to build

Create a new ECS system (RecruitmentSystem) that handles the Recruit command. When a player sends a Recruit command with a desired CombatUnitType:

1. Check Gold balance on the Commander's UnitTypeComponent >= type's RecruitCost
2. Check Formation Template has available slots for that type (slots scaled by Leading Skill, minus currently fielded units of that type)
3. Check total fielded cost (existing units + new unit's cost) <= Leading Skill minus Commander's own cost
4. If all pass: deduct Gold, spawn new CombatUnit entity at Commander's position with the requested CombatUnitType, correct MovementProfile, and all appropriate components (Position, Velocity, Boid, Health, Attack, Movement, Pathfinding, Owner)

The Formation Template is stored as JSONB in the database and loaded into memory at match start. During the match, the template is an in-memory data structure on the session. Slot counts scale proportionally with Leading Skill.

Starting Gold per match: 50. Unspent Gold is lost at match end.

## Acceptance criteria

- [ ] Recruit command validates Gold >= CombatUnitType RecruitCost
- [ ] Recruit command deducts Gold from Commander's UnitTypeComponent on success
- [ ] Recruit command rejects if Formation Template has no available slots for the requested type
- [ ] Recruit command rejects if total fielded cost would exceed Leading Skill minus Commander's own cost
- [ ] Recruited unit spawns at Commander's position with correct CombatUnitType
- [ ] Recruited unit has correct MovementProfile (Light for ArmorLight, Heavy for ArmorHeavy)
- [ ] Recruited unit has all required ECS components (Position, Velocity, Boid, Health, Attack, Movement, Pathfinding, Owner)
- [ ] Recruited unit has same SquadID and Owner as Commander
- [ ] Recruitment fails gracefully when no Commander exists
- [ ] Starting Gold = 50 at match start
- [ ] `go test ./pkg/recruit/ -v` passes
